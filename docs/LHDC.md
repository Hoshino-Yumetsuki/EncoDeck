# LHDC V5 可选组件

在 EncoDeck 的“实验室”页可以下载 LHDC 组件、选择耳机和调整播放参数。
此功能仅供非商店 x64 版试用，需要 Windows 11 22H2（22621）或更新版本，以及支持 LHDC V5 的耳机。

## 免责声明

LHDC 是基于第三方开源项目 LHDC-Win 的实验性功能。实际播放、重连和恢复仍待真机验证，不保证适用于所有设备或系统。使用中可能出现无声、卡顿或需要手动恢复音频的情况。

组件包含测试签名驱动，可能被系统阻止加载。请在了解驱动安装及系统设置变更风险后自行决定是否使用，并自行承担相关风险；EncoDeck 及其开发者在适用法律允许的范围内不对由此造成的损失承担责任。EncoDeck 不会自动更改测试模式、安全启动（Secure Boot）或内存完整性设置。

## 开始之前

- 使用非商店 x64 版 EncoDeck。商店/MSIX 版不提供此功能。
- 电脑运行 Windows 11 22H2（22621）或更新版本，处理器架构为 x64。
- 耳机支持 **LHDC V5**，已在 Windows 中配对并连接。
- 你拥有这台电脑的管理员权限。

如果耳机需要在厂商应用中开启高清音频或 LHDC 模式，请先完成设置。仅支持其他版本 LHDC 的耳机不一定能用，安装时还会检查实际能力。

## 一、准备驱动加载环境

当前组件需要已生效的测试签名模式，并要求内存完整性（HVCI）没有正在强制执行。这些是当前组件的限制，不能仅凭下载成功判断驱动可以加载。

### 1. 保存恢复密钥和当前设置

如果电脑启用了 BitLocker 或设备加密，请先确认能找到恢复密钥，再修改启动相关设置。把安全启动和内存完整性的原始状态记下来，方便以后恢复。

恢复密钥可能保存在 Microsoft 账户、工作或学校账户中。参见[微软的恢复密钥查找说明](https://support.microsoft.com/en-us/windows/security/encryption/find-your-bitlocker-recovery-key)。

### 2. 检查安全启动

按 `Win + R`，输入 `msinfo32` 并回车，在“系统摘要”中查看“安全启动状态”。

如果显示“启用”，需要进入电脑的 UEFI/BIOS 设置，将 **Secure Boot（安全启动）**关闭后，才能按下面的方法启用测试模式。进入方式和选项位置因电脑型号而异，请参考电脑厂商的说明。只修改对应选项，不要清除安全启动密钥，也不要切换启动模式。

关闭安全启动会降低启动过程的安全保护，也可能影响依赖它的软件。如果不愿意修改，可以到此停止，继续使用 Windows 原有蓝牙音频。

### 3. 关闭内存完整性

打开 **Windows 安全中心 → 设备安全性 → 内核隔离详细信息 → 内存完整性**。

如果开关已打开，将其关闭，并按系统提示重启。关闭后会减少对内核的安全保护。

这是当前 LHDC 组件的加载限制。如果设置由组织管理，或重启后仍提示 HVCI 正在强制执行，请联系设备管理员，不要继续修改其他安全策略。

### 4. 启用测试模式

右键点击开始按钮，选择“终端（管理员）”，执行：

```powershell
bcdedit /set testsigning on
```

看到“操作成功完成”后，**重启电脑**。只执行命令、不重启，测试模式还没有对当前运行的系统生效。

- 如果提示“该值受安全引导策略保护，无法进行修改或删除”，请重新检查安全启动是否已经关闭。
- 如果提示“拒绝访问”，请确认打开的是管理员终端。
- 测试模式生效后，桌面右下角通常会出现“测试模式 / Test Mode”字样，这是 Windows 的正常提示。

测试模式会放宽内核驱动的签名信任要求。以上操作和恢复命令参见[微软测试签名说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/the-testsigning-boot-configuration-option)。EncoDeck 不会自动执行这些设置。

## 二、安装并启用

1. 连接耳机，先确认它能通过 Windows 正常播放声音。
2. 打开 EncoDeck 的“实验室”页，点击“下载 LHDC 组件”。**下载不会安装驱动。**
3. 下载完成后，在“音频设备”中选择这台耳机。这里的选择独立于首页，请核对名称和蓝牙地址，一次只能管理一台。
4. 第一次先使用 **48 kHz、24 bit、400 kbps**。
5. 点击“启用 LHDC / 应用参数”，在 Windows 弹出的管理员授权窗口中选择“是”。
6. 等待操作结束。期间声音会暂时中断，请不要强行结束部署进程。若提示需要重启，请先重启电脑。

证书信任和驱动安装由组件的部署流程处理，无需自己双击 INF 文件或手动导入证书。

## 三、确认是否启用成功

回到“实验室”页，选中耳机并点击“刷新”，检查当前模式是否显示为 **LHDC V5**，然后播放音频，确认声音正常。

如果没有声音，先到 **Windows 设置 → 系统 → 声音**，确认输出设备选择的是这台耳机，并检查系统音量和播放器音量。

耳机的 Hi-Res 开关只能说明耳机端的设置，不能单独证明 Windows 已经在使用 LHDC。

## 四、调整播放参数

确认播放正常后，再尝试提高采样率或码率。每次调整后，都需要点击“启用 LHDC / 应用参数”。

- 声音卡顿时，先降低码率，再尝试降低采样率。
- 开启“自适应码率”后，组件会根据连接情况调整码率，所选值作为上限。
- 较高参数是否可用，取决于耳机能力和实际连接情况。第一次使用不必直接调到最高。

## 五、遇到问题怎么办

| 提示或现象 | 处理方法 |
| --- | --- |
| 测试签名模式尚未生效 | 确认启用命令执行成功，并已重启电脑。 |
| 内存完整性 / HVCI 不满足条件 | 检查内存完整性设置，关闭后重启；若仍被强制启用，检查是否由组织管理。 |
| 耳机正在使用其他音频驱动 | 先通过原驱动工具恢复微软蓝牙音频，再尝试启用 LHDC。 |
| 耳机不支持 LHDC V5 或所选参数 | 检查耳机端高清音频设置，并尝试 48 kHz、24 bit、400 kbps。 |
| 列表中没有耳机 | 确认 Windows 已配对并连接耳机，再点击“刷新”。 |
| 启用后卡顿或无声 | 检查输出设备、降低参数；仍不正常时，先恢复 Windows 音频。 |

若操作失败，请保留完整错误信息。错误中包含日志目录时，也请保留该目录，反馈时一并提供。

## 六、停用并恢复系统设置

**先恢复音频，再关闭测试模式。**

1. 打开 EncoDeck，选择使用 LHDC 的耳机。
2. 点击“恢复 Windows 音频”，允许管理员操作并等待完成。
3. 如果提示重启，先重启电脑。重新连接耳机，确认普通蓝牙音频播放正常。
4. 以管理员身份打开终端，执行：

   ```powershell
   bcdedit /set testsigning off
   ```

5. 重启电脑。
6. 如果之前为 LHDC 关闭了安全启动或内存完整性，将它们恢复到原来的状态，并按提示重启。

退出或卸载 EncoDeck 不会自动完成上述恢复。切换到另一台耳机使用 LHDC 前，也应先恢复当前耳机的 Windows 音频。

若音频恢复失败，请保留完整错误信息，不要直接关闭测试模式或删除组件文件，先到项目仓库反馈。

驱动加载检查、证书处理和恢复流程以随版本分发的组件为准，可参考[上游部署脚本](https://github.com/Wayne-u/LHDC-Win/blob/main/scripts/Set-AudioMode.ps1)。

## 组件下载

普通安装包不捆绑 LHDC。LHDC 组件有自己的版本（例如 `0.8.8-r1`，对应 LHDC-Win 0.8.8 的第 1 次构建）和自己的
Release（`lhdc-v0.8.8-r1`），与 EncoDeck 应用版本分开：

- 点击下载后，应用从组件 Release 获取 `EncoDeck-LHDC-<组件版本>-win-x64.zip`，按应用内置
  `src/EncoDeck.Platform/Components/components.json` 中固定的大小和 SHA-256 校验，再核对组件标识和
  上游提交号后解压到 `%LOCALAPPDATA%/EncoDeck/Components/LHDC/<组件版本>-<摘要>`。不经过 GitHub API，
  不受其匿名访问频率限制；中断的下载会从断点续传。显示进度，支持取消与重试。
- 更新 EncoDeck **不会**重新下载组件。发布了新的 LHDC 组件时，不更新 EncoDeck 也能在实验室页
  “更新 LHDC 组件”：打开实验室页时每天最多检查一次，也可以点击“检查更新”。只接受与当前应用的后端接口
  和版本兼容、且大小和 SHA-256 与发布文件一致的组件。更新前，已安装的组件继续可用；更新完成后旧版本即被
  删除，1.10.0 及以前按应用版本存放的旧组件也会被清理。
- 下载本身不安装驱动；安装及恢复仅在点击对应按钮、确认系统管理员授权后执行。
  除上述更新检查外不自动联网。旧的上游面板缓存不视为新运行时。

### 卸载组件

所有耳机都“恢复 Windows 音频”后，点击“卸载组件”即可删除下载的组件文件（约 120 MB）。
LHDC 服务仍为启用状态，或有音频设备仍在使用 LHDC 驱动时，EncoDeck 会拒绝卸载——恢复 Windows 音频
需要这些文件。卸载不会删除部署时安装到系统中、已被停用的 LHDC 服务和驱动包；需要再次使用时重新下载即可。
随离线安装包捆绑的组件属于安装包本身，不能单独卸载。

## 源码构建与云端发布

组件构建从 https://github.com/Wayne-u/LHDC-Win.git 全新克隆，并检出 `components.json` 中固定的提交
（不是构建当天的 main），按上游固定提交拉取编码器与 Windows 驱动样例。拉取失败立即中止。
自编译四个原生后台工具及传输、音频驱动，运行上游测试、生成测试签名并验证包。
不编译或分发上游 WPF UI，运行时仅包含后端、驱动、部署脚本和完整 PowerShell 7。
`runtime.json`（Schema 2）与 `release.json` 记录组件版本、源码仓库和提交；`checksums.json` 记录文件摘要。
许可证随组件保留。构建不会安装驱动或修改系统启动配置。

```powershell
# 普通应用安装包，不捆绑 LHDC
pwsh build/build-installer.ps1
# 构建 components.json 固定的组件和 ZIP；每次都重新拉取源码，输出 component-pin.json（大小与 SHA-256）
pwsh build/publish-lhdc-runtime.ps1 -PowerShellDirectory 'C:/Program Files/PowerShell/7'
# 构建并发布为独立的组件 Release（lhdc-v<组件版本>，需要 gh 登录；不覆盖已发布的版本）
pwsh build/publish-lhdc-runtime.ps1 -PowerShellDirectory 'C:/Program Files/PowerShell/7' -Publish
# 可选：离线捆绑安装包（同一组件版本）
pwsh build/build-installer.ps1 -WithLhdc -LhdcPowerShellDirectory 'C:/Program Files/PowerShell/7'
```

发布新组件版本时：在 `components.json` 中更新 `version`、`tag`、`source.commit` 和文件名，推送
`lhdc-v<组件版本>` 标签。`.github/workflows/components.yml` 在全新 VS2026 构建机通过微软 WinGet 安装匹配
SDK/WDK、拉取上游并编译，发布组件 Release（不会成为仓库的“最新版本”），并在运行摘要中给出大小和
SHA-256；把它们填回 `components.json` 后再发布应用。应用发版不再编译 LHDC：CI 只检查每个固定的组件包
已经发布且大小、摘要一致（`build/verify-components.ps1`），否则阻止发布应用。
每次构建都会生成新的测试证书，字节不同，因此已发布的组件版本不重建、不覆盖，需要时提高 `-r` 修订号。
构建依赖以上游为准，目前包括 MSVC x64、SDK/WDK 28000、KMDF 1.33、
CMake、Ninja、.NET 10、PowerShell 7 x64，以及 Visual Studio 驱动组件和 Spectre 库。

## 支持范围

- 商店/MSIX 版本禁用 LHDC，显示原因与非商店版下载入口；不下载、不启动组件。
  当前实现依赖需要管理员安装的独立驱动和后台服务，仅非商店 x64 版本实验性支持。
- 要求 Windows 11 22H2（22621+）、原生 x64 和真实支持 LHDC V5 的耳机。
- 选项是请求参数，启用时由上游实际探测兼容性；不兼容或失败按上游逻辑恢复。
  操作期间会短暂中断音频，可能需要手动重启；未完成时不宣称已启用。
- 仍使用测试签名，普通系统未必满足驱动加载条件。EncoDeck 不自动修改
  测试模式、Secure Boot 或内存完整性。
- 安装与恢复调用上游部署脚本并读取结果文件；权限取消或失败显示错误，
  不强行终止正在部署和恢复的进程。
- 卸载应用前应先恢复 Windows 音频。关闭应用不会停止上游后台服务。
- 音频设备在此处独立选择，可能与 EncoDeck 当前控制的耳机不同；一次只管理一台。

实际播放、重连与恢复仍需真机测试；编译与只读检查不能代替真机音频验证。
