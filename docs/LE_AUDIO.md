# LE Audio（LC3）连接（实验性）

部分 OPPO 耳机的固件同时支持传统蓝牙（A2DP）和 LE Audio（LC3）。在 OPPO 手机上，LE Audio 由系统蓝牙自行切换；Windows 的“添加设备”找不到这些耳机的 LE 身份，所以总是按传统蓝牙配对。EncoDeck 的“实验室”页提供一个实验性开关，帮 Windows 通过 LE Audio 配对这类耳机。

目前只在 **OPPO Enco X4** 上真机验证过。Enco X4、Enco X3 提供实验性入口；其他 OPPO 型号须回复 LE/BR 开关查询（`0x0136`）或已有 LE 配对，才会显示入口。Enco X3 尚未完成 Windows 真机配对与双耳播放验证。

## 开始之前

- Windows 11 24H2 或更新版本。
- 蓝牙适配器和驱动支持 LE Audio，例如设备管理器中有 Intel 的 “Smart Sound Technology for Bluetooth LE Audio”。
- 建议打开 **设置 → 蓝牙和设备 → 设备 → 可用时使用 LE 音频**。

## 切换到 LE Audio

1. 连接耳机，打开 EncoDeck 的“实验室”页，点击“切换到 LE Audio”并确认。
2. EncoDeck 先通过控制通道关闭双设备连接（应用中的“设备双连”开关），并从耳机回读确认已关闭；确认失败会停止切换并保留原有配对，避免手机抢回连接。随后按提示把两只耳机放回充电盒、打开盖子，长按充电盒按键直到指示灯闪烁。
3. 检测到配对模式后，EncoDeck 删除这副耳机在**本电脑**上的旧配对（手机等其他设备不受影响）。没检测到配对模式时，原有配对不会改动。
4. EncoDeck 自动配对两只耳机，不会弹出 Windows 配对窗口。Windows 11 24H2 起使用系统的成组配对：先配对主耳，Windows 通过 CSIP 报告同组的另一只耳机，EncoDeck 只接受与配对广播中对耳地址完全一致的成员。系统不支持成组配对或没有报告成员时，改为按对耳地址逐个配对。完成后戴上耳机，在声音设置中选择 **扬声器 (耳机名)**。

切换后：

- 成组配对后，两只耳机的 LE 身份和 CTKD 生成的传统节点属于同一个 Windows 设备容器（X4 实测）。旧版逐耳配对会留下两个独立的同名条目：一个是“已连接的麦克风，音频”（第一只耳机 + 控制链路），另一个是另一只耳机。
- **干净重配对后，声音设置中应只有 LE Audio 的“扬声器 (耳机名)”和 LE 麦克风**；两者父链都经过 APXENUM（扬声器最终挂到 BTHLE 设备）。如果还出现经典 A2DP 的“耳机 (耳机名)”端点，说明旧 CTKD 绑定残留：它的父设备是 BTHENUM 0000110B，选中它播放只会到达主耳，表现为单耳有声。这不是 LE Audio 的 CIS。
- EncoDeck 在**两只耳的 LE 链路都已连接，且找到匹配的 LE Audio 渲染端点**时，会尝试只隐藏该经典 A2DP 的 **MMDEVAPI 渲染端点**；通过 `IPolicyConfig::SetEndpointVisibility` 实现，与声音设置里的“禁用”是同一机制，不需要管理员权限。不会禁用 BTHENUM 服务或父设备。条件不满足、检测到多个候选或隐藏失败时不做任何修改，并在卡片上显示警告和“禁用经典音频端点”按钮；“恢复经典音频端点”会重新显示它。
- 降噪、电量等功能照常可用：EncoDeck 改用耳机的 GATT 控制通道。
- LE Audio 下空间音频、Hi-Res、双设备连接等功能可能不可用。

### 如果仍有经典 A2DP 端点

先看声音设置里是否同时存在“扬声器 (3- OPPO Enco X4)”和“耳机 (OPPO Enco X4)”。后者的父设备包含 BTHENUM 0000110B（A2DP Audio Sink），前者是 APXENUM 的 Speaker 端点，两者是不同的音频设备。

- 优先在 EncoDeck 卡片点击“禁用经典音频端点”；它只禁用经典 A2DP 的渲染节点，随时可用“恢复经典音频端点”重新启用。
- 如果按钮不可用，说明两只耳的 LE 链路尚未都连接，或系统没有暴露 LE Audio 渲染端点；此时不要手动禁用 BTHENUM 服务/父设备，否则可能把 LE 音频端点一起变成 phantom，重新启用 BTHENUM 也不一定恢复。
- EncoDeck 会在隐藏经典端点之前先把默认输出切到 LE Audio 的“扬声器”；如果默认切换失败就不隐藏，避免声音落到桌面扬声器。只改默认输出而不禁用经典端点时，Windows 仍可能在某些应用/重连后选回经典端点。

## 恢复传统蓝牙

1. 点击“恢复传统蓝牙”并确认。EncoDeck 会先重新启用之前禁用的经典 A2DP/HFP 渲染端点；如果启用失败会停止恢复并保留配对，避免恢复后没有传统音频。随后只删除本电脑上的双耳 LE 配对和关联的传统蓝牙配对，等待 Windows 清理完成。
2. 点击“打开 Windows 蓝牙设置”，让耳机进入配对模式。
3. 在 Windows 中选择“添加设备 → 蓝牙”，手动重新配对耳机，再选择传统蓝牙音频输出。

EncoDeck 不会自动发起传统蓝牙配对。也可以在 Windows 蓝牙设置中删除两个同名条目，再通过“添加设备”重新添加耳机。

## LC3 重连与控制

EncoDeck 在打开传统蓝牙控制通道前检查 Windows 的 LE 配对记录；有 LE 配对时只使用 GATT，控制连接失败也不会回退 RFCOMM。主耳的 LE 配对缺失时，只要同一设备容器（或配对广播记录的对耳地址、同名同前缀的 LE 配对）里还有另一只耳机的 LE 配对，也视为 LE Audio 配对不完整并拒绝打开 RFCOMM，提示重新切换。配对状态暂时无法读取、或正在切换配对时，等待重试，不尝试传统蓝牙连接，以免打断 LC3 音频。暂时看不到 LE 控制通道不代表 Windows 已经切换音频编码。

控制通道使用有限次数的退避重试，LE 连接恢复后会重新尝试。若提示控制暂不可用，可以稍后点击“重试”或将耳机放回盒中再取出；无需仅因控制失败就删除配对。

运行时分别记录主耳与从耳的 LE 绑定、ACL 连接状态。只有一耳在线时显示单耳提示；ACL 在线和 GATT 控制就绪均不能证明双耳 CIS 正在播放，也不能证明左右同步。

双耳识别优先使用设备容器：成组配对后，同一容器内另一个地址的 LE 配对就是对耳。旧版逐耳配对没有共同容器时，依次使用配对广播记录的对耳地址和 Windows 配对关联端点（AEP）的名称。`BluetoothLEDevice.Name` 有时退化为 `Bluetooth <地址>`，不能用它判断两只耳机是否同名。控制通道监视两个身份，但一次只订阅、写入一耳；失联后关闭旧控制会话，通过有限次数重试在另一耳重新握手，不混合两耳的半帧数据，也不重发执行结果未知的旧命令。另一耳上线可以唤醒已耗尽的控制重试，不重启健康的控制通道。控制角色换到另一耳后（X4 实测：从充电盒取出时），原先订阅的耳机不再推送电量、佩戴等事件；EncoDeck 每 30 秒查询一次电量，查询无应答即改由另一耳重新握手，因此空闲时状态最迟约 30 秒后更新。

切换配对时，旧蓝牙节点清理超时会停止后续配对，避免旧 A2DP/HFP 节点被 CTKD 带回。双耳绑定后另行等待双耳 ACL 就绪；超时显示“已配对，等待连接”，不声称音频成功。应用切换入口会尝试写入并回读 `0x0433`，其结果记入本机日志；它不是 LC3 启动命令。

LC3 切换的首个必要步骤是通过控制器写入双设备连接关闭并回读确认。缺少控制通道、写入/回读失败、超时或设备拒绝都会停止后续模式切换和配对操作；不能仅信任缓存里的“已关闭”。保留 LE 配对时，OPPO 控制器拒绝从应用重新开启双设备连接；需要恢复传统蓝牙后才能重新开启。该保护不能约束手机重新修改耳机设置或手动切换设备，不能作为永久排他连接保证。

诊断命令：`EncoDeck.Probe le-audio --device "OPPO Enco X4" --seconds 120` 使用现有 LE 绑定测试重连并记录双耳链路变化；添加 `--pair --confirm-write` 才会先关闭并确认双设备连接、等待配对广播并替换本机配对。`EncoDeck.Probe multipoint-off --device "OPPO Enco X4" --confirm-write` 仅关闭双设备连接并回读，不更换配对。上述命令不验证声学同步。

## 工作原理

以下为 Enco X4 实测结果。

| 事实 | 证据 |
|---|---|
| 配对模式下，主耳以与传统蓝牙相同的公共地址发可连接广播，flags 为 `0x18`（双模，**无** LE 通用可发现），扫描响应含 PACS `0x1850`、ASCS `0x184E` | X4 实测 |
| 主耳 LE 上有 VCS、CSIS、MICS、ASCS、BASS、PACS、CAS、TMAS 以及 OPPO `079A` 控制服务 | X4 实测 |
| 另一只耳机不发广播。它的地址在主耳扫描响应的厂商数据 `0xBF0D` 中：`[00 00][地址 LE ×6][…]` | X4 实测（直接连接该地址可配对成功） |
| 先对主耳做 LE 配对，Windows 会通过 CTKD 自动生成传统配对，通常只有控制通道 ELNK；但部分 Windows/驱动组合仍会暴露经典 A2DP 渲染端点（同一副耳机出现“耳机”和 LE“扬声器”两个输出） | X4 实测 |
| 已有传统配对时再做 LE 配对，会得到三个独立容器、两套音频端点，所以要先删除全部配对 | X4 实测 |
| 断开重连后 Windows 只恢复 LE 链路；控制改走 GATT `079A`（写 `0100079A`，通知 `0200079A`） | X4 实测 |
| 不需要写任何耳机设置。LE/BR 开关 `0x0433` 关闭时，配对、重连和双耳播放都正常 | X4 实测 |
| 手机上的 LE Audio 切换由手机系统蓝牙完成，与耳机控制协议无关 | 手机端行为观察 |

## 左右耳听起来不同步怎么办

LE Audio 下，左右耳经常相差约 7.5 ms（一个音频帧），成组配对也不能避免。听起来像声音偏向一侧、人声不在正中间，或者带一点“空心”的回声感。原因和测量数据见下方“已知问题”。

偏差在**每次开始播放**时决定，播放过程中不会自己变好或变坏，所以处理办法就是让 Windows 重新开始一次播放：

1. **暂停所有正在发声的程序，等 5 秒以上再继续播放。** 包括浏览器里的视频或音乐标签页、游戏、通话软件；只要还有一个程序在发声，Windows 就不会重建音频流。
2. 还是不对，就**关掉播放器（或浏览器标签页）再重新打开**。有些播放器暂停时并不会释放音频流，只有关掉才会真正停止。
3. 仍然不对，就**把两只耳机都放回充电盒、关盖 10 秒**，再取出佩戴。
4. 对同步特别敏感时（例如看视频、玩游戏），可以先**恢复传统蓝牙**。A2DP 不经过 LE Audio 的同步组，左右耳的同步由耳机自己处理（EncoDeck 尚未实测 A2DP 下的左右偏差）。

怎么判断是否同步：播放一段**单声道**的人声或节拍（例如新闻播报、节拍器），同步时声音在头部正中间；如果明显偏向一侧，就说明这次播放错开了一帧。

## 已知问题

- 旧版逐耳配对时，另一只耳机在 Windows 中是独立的设备容器。改用成组配对重新切换即可合并。
- CTKD 经典 A2DP 端点可能残留：它只连主耳，选中它播放会单耳有声。EncoDeck 只会在双耳 LE 链路和 LE 渲染端点都就绪时禁用该经典 A2DP 渲染节点；不要禁用 BTHENUM 服务/父设备。
- **左右耳常常相差一帧（约 7.5 ms）。** 偏差在开始播放（建流）时决定，播放中不会变化：要么对齐（±0.1 ms），要么一侧恰好晚一个 ISO 间隔。2026-10-26 在成组配对（双耳同一设备容器、双耳 LE 链路均在线）后重测：8 次有效建流中 7 次左耳晚 7.49–7.51 ms，1 次对齐（+0.006 ms）；同一次建流内多次测量的离散不超过 0.05 ms。**成组配对没有消除错帧。** 此前的抓包显示错位时双耳处于同一 CIG（CIS 0/1），声道分配为 Front Left / Front Right，48 kHz、7.5 ms、每帧 90 字节，presentation delay 40 ms，ISO 数据走厂商数据路径（Data Path ID 1），HCI 上看不到音频负载。应用目前没有可修正 CIS 参数或耳机播放触发时间的接口。

  公开资料中最接近的案例是 Linux 上的 [BlueZ #515](https://github.com/bluez/bluez/issues/515)：Galaxy Buds2 Pro + Intel AX210，左右从开始播放就相差约 10 ms，两路 CIS 的发送延迟明显不同；Linux 通过读取每路发送延迟并在 PipeWire 中修正来缓解，并说明仍可能错开整数个包。该案例与本机（Intel `8087:0033`，Windows SST offload）同为 Intel 控制器，但 Windows 走厂商数据路径，不能直接证明根因相同。

  测量方法：左右声道同时播放频带不重叠的扫频（耳机未入耳时用 1.5–3.5 kHz / 4.5–9 kHz，低于约 1.5 kHz 的频带在未入耳时太弱），外部麦克风录音，匹配滤波定位到达时间；同一次建流内再对调频带，抵消频率相关的时延。每次测量都新建输出流、只播放到 LE 扬声器端点（不改默认输出、不打开耳机麦克风），结束后空闲数秒再测下一次；空闲多久 Windows 才真正拆除 CIS 尚未单独验证。环境为 Windows 11 build 26340、Intel Smart Sound Technology for Bluetooth LE Audio 20.40.12849.0、Intel 蓝牙驱动 24.80.0.2、Enco X4 固件 130/130/100。
